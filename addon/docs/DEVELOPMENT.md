# Разработка Colorize2Core

В корне проекта:

```bash
pnpm install
pnpm build
pnpm exec tsc --noEmit -p tsconfig.json
pnpm test:ui
pnpm test:contrast
pnpm test:performance
pnpm test:lifecycle
pnpm sync
```

`pnpm build:sync` собирает и устанавливает, `pnpm dev` следит за исходниками.
Сборка находится в `dist/31c62ba2-b6f6-4ba7-934e-39146eccfe69/`.
`addon/` копируется в пакет, `addon.config.mjs` формирует metadata.json.
Установка сохраняет пользовательский pulsesync.settings.json и резервирует старый пакет.
Путь установки переопределяется переменной `PULSESYNC_ADDONS_DIR`.

Тема собирается отдельно из `../Colorize-2/` теми же командами install/build/sync.
Настройки редактируются в `Colorize-2/addon/handleEvents.json`, не в Core.

Тестам интерфейса нужен Chrome; путь задаётся через `CHROME_BIN`.
Они используют отдельный временный профиль, без пользовательской сессии,
и CSS соседнего проекта Colorize-2. Предусловие: выполненная сборка Core.
Сравнение производительности с архивом использует `COLORIZE_BASELINE`
(полный путь к старому main.ts) и команду
`pnpm test:performance --compare-backup`. Обычный тест архива не требует.

После изменения установленных файлов требуется обновление списка дополнений PulseSync;
для замены работающего скрипта может потребоваться перезагрузка Яндекс Музыки.
Браузерные фикстуры проверяют изолированные сценарии. Проверка поведения в Яндекс Музыке выполняется отдельно.

`test:lifecycle` проверяет отсутствие активности без темы, очистку при отключении,
восстановление inline-размеров, повторные включения и отмену обработки загружаемой обложки.
